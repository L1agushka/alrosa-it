# Групповые политики аудита

Группа определяется точным, очищенным от пробелов значением department. Пустое значение становится «Общий». Имена чувствительны к регистру. Политика «Общий» относится только к своей группе и не является родительской для других групп.

## Хранение и миграция

Таблица group_policies хранит уникальное group_name, settings и rules в PostgreSQL. Обновления правил блокируют строку на время транзакции. Создание одной группы конкурирующими запросами защищено уникальным индексом и INSERT ON CONFLICT.

Миграция a120_group_policies создаёт таблицу, копирует прежние глобальные веса и JSON-правила отдельно в существующие группы, добавляет workstations.installed_software и восстанавливает известное ПО старых аудитов из связей. Неизвестное ПО новых аудитов сохраняется без необходимости добавлять его в общий каталог.

Для существующей БД с историей миграций достаточно штатного запуска контейнера. БД, созданная вручную через create_all и не имеющая alembic_version, требует отдельной сверки схемы перед переходом. Автоматический stamp не выполняется.

## Контракты API

Все запросы требуют access JWT. Читать могут viewer, analyst и admin. Изменять могут analyst и admin.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/v1/criteria/groups | Политики групп из реестра, справочника отделов и созданных политик |
| PUT | /api/v1/criteria/groups/{group} | Создать или заменить настройки одной группы |
| GET | /api/v1/policy/custom-rules?group=... | Правила одной группы |
| POST | /api/v1/policy/custom-rules?group=... | Создать правило |
| DELETE | /api/v1/policy/custom-rules/{id}?group=... | Удалить правило только в выбранной группе |
| POST | /api/v1/policy/custom-rules/upload?group=... | Валидировать и импортировать JSON-массив |
| GET | /api/v1/policy/custom-rules/export?group=... | Экспортировать правила группы |
| POST | /api/v1/policy/nlp-match?group=... | Сопоставить ПО с учётом правил выбранной группы |

В policy API параметр group обязателен. Одинаковый паттерн в разных группах разрешён, повтор в одной группе возвращает 409. Неизвестное правило при удалении возвращает 404. Пустой паттерн, неверный статус или вес вне 0–100 возвращают 422.

Импорт сначала валидирует весь файл. Ошибочный файл не изменяет существующие правила. Идентификаторы экспортированного файла при импорте заменяются новыми. Дубли пропускаются по паттерну в пределах выбранной группы. Лимит JSON — 1 МиБ.

Старый PUT /criteria/weights/{code} возвращает 410 с адресом нового API. GET /criteria/weights оставлен как архив исходных глобальных значений.

## Расчёт

Минимум оборудования равен большему из минимума ОС и порога группы. Для каждой программы выбирается наиболее длинный подходящий паттерн своей группы. Локальное правило перекрывает каталог, включая явно разрешённое исключение native_ready. При равной длине побеждает первое правило в сохранённом порядке.

Статус blocker всегда означает волну 3, независимо от веса. native_ready не добавляет проблему или вес. manual_check, alternative, alternative_available и non_target требуют действий и дают минимум волну 2. Поле severity сохраняется для совместимости с прежним форматом, а поведение локального правила определяет status.

Без локального правила применяется каталог выбранной ОС. Неизвестное название увеличивает долю ПО для ручной проверки. Превышение maxGap требует действий. Критический аппаратный вес или вес неизвестного ПО от 50 переводит соответствующую проблему в волну 3. Остальные проблемы дают волну 2. Score суммирует веса и помогает приоритизации, но не заменяет явные условия волн.

Настройки в интерфейсе — текущий предпросмотр. Серверный снимок создаётся при загрузке файла и не пересчитывается задним числом. Новые названия неизвестного ПО доступны после перезагрузки страницы.

## Данные инвентаризации

Обязательные колонки: workstation_id, department, ram_gb, cpu_cores, disk_gb, installed_software. Названия программ разделяются точкой с запятой. Поддерживаются CSV UTF-8 и XLSX.

Идентификаторы в одном файле должны быть уникальными и непустыми. Числовые характеристики должны быть целыми, конечными, неотрицательными, не больше 1048576. Ошибочная строка возвращает понятную ошибку до записи аудита. Лимиты: 10 МиБ и 20 000 строк.

## Проверка

Серверные интеграционные тесты проверяют разные результаты одинакового ПО по группам, пороги, исключения, неизменность истории, сохранение неизвестного ПО, валидацию импорта, отсутствие доступа без JWT и запрет записи для viewer. Клиентские тесты проверяют те же основные правила волн и пограничные значения.

Синтетический сценарий scripts/demo.py ожидает волны 1, 3, 2, 2, 3, 1. Запуск повторяемый, при этом каждая загрузка создаёт новый снимок аудита.
