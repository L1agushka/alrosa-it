# ML-прототип: обучение и сценарный расчёт

## Что изменено

Calibrated Random Forest v2 использует единый контракт из `backend/app/ml_contract.py`: 10 признаков, одна схема для обучения и API. Нулевые характеристики и пустой список ПО сохраняются; модель не получает придуманные четыре программы. Периферия пока не собирается: принято 2 устройства с явным предупреждением.

Датасет `ml/data/migration_dataset.csv` синтетический, 2500 записей. Стратифицированное разбиение с seed=42: 2000 для обучения, 500 для теста. Калибровка sigmoid выполняется на трёх фолдах только обучающей части; отложенный тест в обучение и калибровку не попадает. Сравнение проводится с Logistic Regression на том же разбиении. Важность признаков измерена перестановкой на тесте по ROC-AUC; это общая чувствительность модели, а не причинное объяснение отдельной станции.

| Метрика теста | Random Forest v2 | Logistic Regression |
| --- | ---: | ---: |
| Accuracy | 0.8380 | 0.7660 |
| F1 | 0.7793 | 0.6795 |
| ROC-AUC | 0.9120 | 0.8607 |
| Brier score | 0.1159 | 0.1493 |
| Log loss | 0.3666 | 0.4549 |

Матрица ошибок RF, строки — истинный класс 0/1, столбцы — прогноз 0/1: `[[276,23],[58,143]]`. Эти показатели не измеряют качество на реальных инцидентах предприятия.

## Воспроизведение

Из корня репозитория с зависимостями backend:

~~~sh
python ml/train.py
~~~

В Docker, не устанавливая Python на хост:

~~~sh
docker compose cp ml backend:/tmp/alrosa-ml
docker compose exec -e PYTHONPATH=/app backend python /tmp/alrosa-ml/train.py --data /tmp/alrosa-ml/data/migration_dataset.csv --output /tmp/ml-v2
docker compose cp backend:/tmp/ml-v2/. backend/app/ml/
~~~

После обновления артефактов пересобрать backend. Активные артефакты — только `backend/app/ml/`. Исторические файлы `ml/models/` сервисом не читаются. В `meta.json` сохранены хеши датасета, модели и ID тестовой части, версии библиотек, диапазоны признаков и метрики. ML-зависимости закреплены в requirements.txt. Несовпадение схемы, версии scikit-learn или SHA-256 отключает модель; резервный индекс явно обозначается и не получает метрики RF.

## API и сценарии

`GET /api/v1/stats/ml-risk?session_id=...` выбирает конкретный аудит; без параметра — последний. Отсутствующий аудит возвращает 404. Исторические аудиты не смешиваются.

`POST /api/v1/stats/ml-risk/simulate?session_id=...` принимает только булевы поля `upgrade_ram`, `replace_cad`, `web_1c`, `compatible_crypto`. Дополнительные поля запрещены. Сервер вычисляет базовый и сценарный прогноз одной моделью; снижение риска не гарантируется и не принуждается. Изменение выражается в процентных пунктах. Для замены CAD/крипто снимаются только соответствующие учтённые программные блокеры в признаках сценария. Записи БД, статусы и волны аудита не изменяются.

## Ограничения

- Обучение на синтетике не заменяет проверку на реальных данных. Вероятности — исследовательские оценки модели.
- Новые подразделения и значения вне диапазона обучения выделяются рядом со сводкой и в деталях станции.
- Низкая оценка ML не снимает блокер и не подтверждает совместимость драйверов, лицензий или рабочих сценариев.
- Предположение о замене ПО не является гарантией успешного перехода. Часы простоя и бюджет без реальных исходных данных не рассчитываются.
- Наблюдаемые признаки не называются локальным объяснением Random Forest. Для внедрения нужны измеренная периферия, реальные результаты перехода, внешняя валидация и мониторинг сдвига данных.

Методические источники: [CalibratedClassifierCV](https://scikit-learn.org/stable/modules/generated/sklearn.calibration.CalibratedClassifierCV.html), [сохранение моделей](https://scikit-learn.org/stable/model_persistence.html).
