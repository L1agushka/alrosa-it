# AVA / Mineral — результат редизайна

Полный визуальный редизайн ALROSA IT: входная страница и восемь рабочих разделов. Ветка `codex/ava-premium-redesign`; исходное состояние, включая прежние пользовательские изменения, сохранено в коммите `44ce492`.

Отдельный тестовый стенд `/ml-dashboard.html` исключён из объёма по указанию пользователя. Его оформление и поведение сохранены.

## Визуальная система

Тёплый графит, слоновая кость и приглушённая медь связывают инженерный интерфейс с образом огранённого минерала. Светлые непрозрачные рабочие поверхности помогают читать плотные данные; графитовая навигация обозначает постоянную структуру. Алмаз ALROSA сохранён. AVA — типографическая подпись команды, а не замена логотипа продукта.

Основные токены: фон `#f0ede6`, поверхность `#faf8f3`, текст `#302e29`, вторичный текст `#6d675d`, акцент `#8b4d34`, графит `#252623`; статусы используют зелёный, янтарный и красный вместе с текстом. Manrope сохранён для рабочих экранов; курсивная Georgia используется как выразительный акцент лендинга. Общие отступы, границы, фокус, состояния и адаптивность описаны в `src/design/`.

### Материал Liquid Glass

`OpticalSurface.jsx` напрямую использует неизменённый `glass-lab/vendor/maps.ts`: физическую карту смещений с профилем squircle, маску внутренней поверхности и направленную карту блика. MIT-лицензия остаётся в `glass-lab/vendor/LICENSE`; исследование источников — в `glass-lab/RESEARCH.md`.

- Subtle: спокойная поверхность для неактивных рабочих элементов.
- Standard: прозрачность и умеренное размытие, в частности панель конфигуратора.
- Premium: SVG displacement и оптическая кромка для активной навигации, переключателя карты, заголовков диалогов и акцентов лендинга.

В продукте используется один проход смещения вместо трёх цветовых проходов стенда. Геометрия кешируется, размер поверхности ограничен 180 000 пикселей; таблицы не получают тяжёлые фильтры. Преломление включается для поддерживаемой Chromium-ветки; остальные браузеры получают спокойный CSS fallback. Предусмотрены reduced motion, reduced transparency и forced colors. Это улучшение оформления, не условие доступа к действиям.

## Проверки

Проверено в установленном Chromium через имеющийся Playwright runtime, без установки зависимостей. В среде отсутствует `npx`, поэтому использован уже доступный модуль Playwright. Системный Node 18 не подходит для Vite 8; сборка выполнена имеющимся более новым Node из runtime Codex.

- Production-сборка Vite — успешна; JavaScript около 339 КБ, gzip около 103 КБ.
- Oxlint — без ошибок; 15 ранее существовавших предупреждений (в исходном состоянии 16).
- Восемь рабочих разделов на ширинах 1440, 720, 390 и 320 CSS px: 32 проверки без горизонтального переполнения документа. Широкие таблицы прокручиваются внутри контейнера.
- Лендинг на desktop, 390 и 320 px; мобильное меню, Escape, секция команды и переход в приложение.
- Дополнительно проверен перенос при эквиваленте 200% масштаба: 720 CSS px вместо 1440. Это проверка reflow, а не нативного browser zoom.
- Реестр: поиск, отдел, статус, сортировка, дозагрузка 24 → 48, пустой результат, сброс; карточка устройства и все три вкладки; закрытие Escape и возврат фокуса.
- Импорт: отображение ошибки; скачивание шаблона; изменение критериев; офисная карта; CSV и печатный режим отчёта.
- Конфигуратор: разбор схемы, выбор памяти, автоподбор. ML: сценарий и сброс. NLP: сохранение тестовой политики, предупреждение и отмена.
- Загрузка и недоступная ML-оценка, отсутствие данных, reduced motion, forced colors и CSS fallback оптики.
- Нет необработанных JavaScript-ошибок в основном браузерном прогоне.
- 16 сравнений с исходной версией совпали: сводки, строки, фильтры, детали, playbook, критерии, CSV, конфигуратор, ML-сценарий и отправляемые запросы. При сравнении текста нормализованы только заменённые декоративные значки экспорта.
- AST 46 защищённых выражений и обработчиков совпадает с исходной версией: расчёты, адаптеры, импорт/экспорт, ML, NLP и конфигуратор.
- SHA-256-аудит исходных файлов: изменены только перечисленные визуальные frontend-файлы, исходные файлы не удалены. Backend, `engine.js`, manifests/lockfiles, данные, инфраструктура и инструкции не изменялись этим редизайном.

В контролируемом headless-прогоне 60 кадров прокрутки медиана интервала кадров около 16,7 мс; p95 16,7–16,8 мс. Это характеристика конкретного прогона, не гарантия частоты кадров на пользовательском GPU.

### Данные проверки и воспроизведение

`qa/premium-check.cjs` перехватывает все API-запросы. Инвентаризация берётся из существующего `alrosa_audit_100_workstations.csv`; ML, каталог и NLP используют явно помеченные QA-ответы. Они не добавлены в приложение, не записаны в БД и не являются результатами анализа предприятия.

Для повторения нужен уже установленный Playwright и Chromium. Запустите frontend обычной командой проекта с подходящей версией Node, затем из корня:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
CHROMIUM_PATH=/absolute/path/to/chromium \
node frontend/qa/premium-check.cjs
```

Если модуль и браузер доступны стандартным способом, переменные не требуются. `QA_URL` меняет адрес (по умолчанию `http://127.0.0.1:5173/`), `QA_OUTPUT` — каталог результатов. Скрипт завершится ошибкой при нарушении проверяемых сценариев, переполнении, ошибках браузера или потере возврата фокуса.

Артефакты в корне проекта:

- `output/playwright/premium-before/`, `premium-before-filled/` — исходные снимки.
- `output/playwright/premium-after/` — текущий лендинг и настоящие пустые рабочие экраны, загрузка и fallback.
- `output/playwright/premium-validation/` — снимки с изолированными QA-ответами; `checks.json`, `regression-comparison.json`, `protected-expressions.json`, `file-audit.json`.
- `output/playwright/premium-baseline-validation/` — результаты тех же действий в исходной версии.

## Оставшиеся ограничения

Backend на порту 8000 в этой среде недоступен. Реальные успешный импорт, сохранение в БД и ответы ML/NLP сквозным образом не проверены; состояния заполненных экранов и запросы проверены изолированно. При открытии обычного приложения данные не подменяются тестовыми.

Firefox, Safari, iOS и слабые GPU здесь не запускались. Ветку fallback проверяли в Chromium с отключением улучшенной оптики через идентификацию браузера; это не тест движка Firefox. Контраст базовых пар токенов проверен (основной текст 12,78:1, вторичный 4,79:1, статусные пары не ниже 4,62:1), но полного автоматизированного WCAG-аудита всех динамических фонов не проводилось.

Известные ограничения исходных данных и алгоритмов из `AGENTS.md` сохранены: запасные аппаратные/программные значения, различия серверной и локальной оценки, локальная эвристика риска, неполный контракт импорта. Редизайн их не исправляет и не превращает оценку в подтверждение совместимости.
