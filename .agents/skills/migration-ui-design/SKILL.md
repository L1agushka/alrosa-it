# Migration UI Design

Сначала прочитай корневой `AGENTS.md`: карту проекта, защиту функциональности и ограничения данных. Пути ниже относительно корня проекта. Начинай редизайн только по отдельной задаче пользователя; создание скилла не разрешает менять интерфейс.

## DISCOVER

- Проверь git status; сохрани чужие незакоммиченные изменения. Изучи `frontend/src/App.jsx`, затрагиваемые компоненты, `ui.jsx`, `engine.js`, `App.css`, `index.css`, `landing.css` и фактический CSS-каскад.
- Проследи данные от API через схемы и адаптер до отображения. По необходимости читай `backend/app/schemas/audit.py`, `services/parser.py`, `services/scoring.py`, `models/enums.py`. Чтение не разрешает менять эти файлы.
- Зафиксируй сценарии и исходные результаты на одном наборе данных: значения, статусы, волны, блокеры, фильтры, действия, экспорт. Учти loading, empty, error, неизвестные значения и большой парк.
- Изучи текущую идентичность: ALROSA IT, алмаз, тёмная палитра, голубой акцент, Manrope. Отдели серверный аудит, frontend-пересчёт, ML, локальные эвристики и запасные значения. Название SHAP не доказывает происхождение вычисления.

## DESIGN

- Сформируй цельную концепцию на основе существующей идентичности: типографическая иерархия, модульная сетка, плотность, палитра, статусы, контекстные действия и визуализация. Объясни пользу для инженерной задачи; не копируй чужой продукт.
- Для реестра предпочитай сравнимые строки и плотные читаемые таблицы там, где они упрощают работу. Сохраняй поиск, фильтры, сортировку, дозагрузку и открытие деталей.
- В деталях разделяй CPU, RAM, диск, ПО, причины и рекомендации. Показывай только доступные характеристики и единицы. Модель CPU, тип накопителя и периферия не должны появляться из предположений.
- Различай «совместимо», «вероятно совместимо», «требует проверки», «несовместимо», «нет данных» по имеющимся основаниям. Это семантика UI, а не разрешение добавлять enum или менять алгоритмы. Готовность к волне, риск, наличие аналога и подтверждённая совместимость — разные понятия.
- Показывай ограничения и происхождение оценки. Отсутствие блокера или данных не доказывает совместимость. Стоимость и эффект what-if без подтверждения обозначай как оценки.
- Исключи generic SaaS dashboards, бессмысленные градиенты, избыточный glassmorphism, огромные скругления, бесконечные одинаковые карточки, случайные иконки и необоснованные анимации. Предусмотри контраст, текстовые статусы, клавиатуру, reduced motion и адаптивность.

## IMPLEMENT

- Улучшай согласованный экран постепенно, переиспользуя компоненты и CSS-переменные. Сохраняй props/callbacks, обработчики, доступ к действиям и существующие возможности.
- Не меняй `evaluate`, серверный скоринг, ML/эвристики, API, импорт/экспорт, схемы, авторизацию, БД, backend и инфраструктуру ради UI. Не добавляй зависимости без обоснования и согласования.
- Не заменяй реальные ответы фиктивными характеристиками, ПО, периферией, процентами или рекомендациями. Изолированные тестовые данные должны быть явно обозначены и не попадать в рабочие результаты.
- Обнаруженные дефекты данных описывай отдельно. Если честная подача требует изменения защищённого контракта или алгоритма, запроси отдельное разрешение именно на это изменение и продолжай независимую UI-работу.

## VALIDATE

- Проверь diff на соответствие задаче и сохранность чужих правок. Сверь данные, статусы, волны, причины, счётчики, действия и выгрузку до/после при одинаковой ОС и критериях.
- Если доступны runtime и браузер, используй установленный скилл `playwright` для визуальной проверки. Сначала проверь `npx`; отсутствие глобального CLI само по себе не препятствие. При недоступности явно сообщи причину и что браузерная проверка не выполнена. Не устанавливай зависимости и браузеры без согласования.
- При доступном браузере сравни снимки до/после на одинаковых данных: desktop и узкий экран, длинные значения, большой парк, пустой поиск, loading, error, неизвестные данные. Не импортируй тестовые аудиты в рабочую БД без разрешения.
- Проверь клавиатуру, видимый фокус, подписи, семантику таблиц и диалога, возврат фокуса, контраст WCAG AA, масштаб 200%, prefers-reduced-motion. Цвет дополняй текстом; графики — доступными значениями и подписями.
- Для UI-изменений запускай имеющиеся `npm run build` и `npm run lint` из `frontend`, если окружение подготовлено. Не выдавай просмотр исходников за браузерный тест и не отмечай непроведённые проверки успешными.

## REFINE

- Устрани визуальный шум, разнобой плотности и отступов, слабый контраст, обрезанные значения. Согласуй таблицы, фильтры, панели, диалоги, единицы и выравнивание чисел.
- Микроинтеракции должны объяснять действия и состояния, не изображать завершённый аудит раньше фактического результата.
- Заверши отчётом о конкретных улучшениях, выполненных проверках и оставшихся ограничениях данных. Не выдавай качество визуальной подачи за доказательство совместимости.
